## 一、产品定位

**一个伪装成购物 App 的情绪化消费觉察工具。**

真实痛点：很多人在深夜情绪低落时冲动下单，其实并不真的需要那件商品，
只是想用「下单」这个动作缓解压力。

产品思路：用一套和美团一样真实、顺滑的购物体验承接这种冲动，
再通过每周的消费周报让用户自己看见消费习惯——不说教、不评判。

## 二、核心设计原则

产品成立的根基，任何功能都不得违背：

1. **前台绝不暴露真实意图** —— 全程像正常网购，不出现任何"假装""情绪""克制"之类字眼。
   前台越真实可信，周报的觉察反差才越有力量。
2. **价值后置到周报** —— 前台不剧透，产品真正的价值只在用户回看周报时自然浮现。
3. **不问心情，只看行为** —— 真实购物不会问你心情。改用「下单时段」这一真实行为数据做洞察，
   深夜下单本身就是情绪信号。
4. **温和不说教** —— 周报用客观数据 + 缓冲建议（"先放购物车，睡一觉再决定"），
   让用户自己觉察，而非被教育。

## 三、核心闭环

必须完整跑通，一环都不能断——它是"真实购物体验"的载体：

```
首页店铺流 → 进店看菜单 → 加入购物车(按店铺分组)
    → 确认订单(地址/配送/支付) → 支付成功
    → 骑手配送追踪 → 确认收货 → 消费周报
```

## 四、功能需求

### 4.1 购物前台（对标美团外卖，追求逼真）

| 模块 | 需求 |
|------|------|
| 店铺体系 | 店铺流首页 + 分类筛选 + 店铺详情页（店招/评分/月售/公告/配送信息/菜单/实时结算条） |
| 商品浏览 | 美团式商品卡（评分、月售、配送时长、券后价+原价划线+满减标签）、商品详情、用户评价区 |
| 限时秒杀 | 首页横向秒杀位 + 真实倒计时（距当日 24:00） |
| 搜索 | 按名称/描述/分类/标签/店铺名/品牌匹配，含搜索历史、热门词、无结果空态 |
| 收藏 | ❤️ 收藏/心愿单，收藏列表显示所属店铺 |
| 购物车 | 跨店按店铺分组、分别小计、增减数量、删除、就地步进器 |
| 下单结算 | 真实收货地址、配送时段可选、备注、支付方式、按原价自动算"已优惠" |
| 物流追踪 | 五阶段推进（商家接单→打包→骑手取货→即将送达→已送达）+ 骑手卡 + 预计送达倒计时 |
| 订单管理 | 确认收货、订单详情（店铺名/明细/订单号）、再来一单 |

### 4.2 觉察后台（产品真正的价值）

| 模块 | 需求 |
|------|------|
| 消费周报 | 本周下单总金额、笔数、累计消费 |
| 时段洞察 | 下单时段分布可视化（深夜/上午/下午/晚间） |
| 深夜提示 | 深夜下单时触发温和提示 + 缓冲建议，不说教 |
| 克制正反馈 | 统计"收藏了却没下单"的商品 = 忍住的冲动金额，正向强化克制 |

## 五、内容与技术约束

- **搞笑化品牌**：门店用现实品牌的搞笑化名（麦当劳→麦当当、肯德基→啃德鸡、
  喜茶→喜茶茶、海底捞→海底捞捞），纯属虚构、营造真实感又规避侵权。
  当前 16 家店铺、64 款商品。
- **纯静态、零构建**：HTML + CSS + 原生 JS 四层架构
  （`data.js` 数据 / `state.js` 状态 / `views.js` 渲染 / `app.js` 路由控制）。
- **本地持久化**：数据存浏览器 `localStorage`，刷新不丢，换浏览器/清缓存即重置。
- **移动端优先**：480px 宽度容器，模拟手机 App 体验。
- **演示加速**：配送每 15 秒推进一阶段（`state.js` 里的 `STEP_MS`），约 1 分钟走完全程。

## 六、产品边界

这是一个帮助觉察和缓解情绪化消费的**小工具，不能替代专业的心理支持**。
如果情绪长期低落，请认真对待，必要时寻求专业帮助。

这条伦理底线必须在产品中保留（当前置于 README 末尾）。

## 七、验收标准

产品视为"可用"，须满足：

1. **闭环完整**：从选商品到送达再到周报，全链路无卡点跑通。
2. **前台可信**：任一界面都不暴露产品真实意图，体验与真实外卖 App 无异。
3. **周报有效**：多笔下单后，周报能正确呈现金额、时段分布，深夜下单能触发温和提示。
4. **数据一致**：加购、分组、金额计算、订单快照在各页面间保持一致。
5. **跨会话保持**：刷新页面后购物车、订单、收藏、周报数据不丢失。

> 已通过 jsdom 浏览器级端到端测试：主闭环 24 项 + 边界 8 项全部通过。
