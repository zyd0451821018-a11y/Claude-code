# 丑团 — 打包部署流程

> 参考 [驭流-打包部署流程] 的范式整理。本项目比电商作图工作台还简单：**纯静态站**、
> 无后端、无数据库、无 .env 密钥，用户数据全在访问者浏览器 localStorage，服务端零状态。

## 环境说明

- 本地开发：Mac（arm64）
- 服务器：`Liyibin@8.141.121.22`，Linux/amd64
- 服务端口：**`9000`**（映射容器内 `80`）—— ⚠️ `8011` 驭流、`8012` 作图工作台已占用，勿重合
- 域名：`www.choutuan.cloudwaveai.cn`（兼收 `choutuan.cloudwaveai.cn`）
- 镜像名：`choutuan-web:latest`，容器名：`choutuan-web-1`，compose 服务名：**`web`**
- 架构：**单容器**，单阶段构建（`nginx:1.27-alpine` 直接托管静态产物，无 Node/Python）

------

## 一、本地打包

```bash
cd <仓库目录>/choutuan   # git clone 后的 choutuan 子目录

DOCKER_BUILDKIT=1 docker buildx build \
  --platform linux/amd64 \
  -f Dockerfile.prod \
  -t choutuan-web:latest \
  --load \
  .
```

> - `--load` 必须加，否则镜像不写入本地 Docker daemon。
> - 单阶段：站点本身零构建（原生 JS 四层架构），Dockerfile 只做 COPY + nginx 配置。
> - 镜像约 **70MB**（nginx:alpine ~50MB + 站点 18MB，其中 632 张商品图 17MB）。
> - 若拉 `nginx:1.27-alpine` 报镜像源抖动，先 `docker pull --platform linux/amd64 nginx:1.27-alpine`
>   单独拉一次再构建。

------

## 二、导出镜像

```bash
docker save choutuan-web:latest | gzip > /tmp/choutuan-web.tar.gz
```

约 **65MB**，比作图工作台（300MB+）小得多。

------

## 三、上传到服务器

```bash
sshpass -p '<服务器密码>' scp -o StrictHostKeyChecking=no \
  /tmp/choutuan-web.tar.gz Liyibin@8.141.121.22:/tmp/choutuan-web.tar.gz
```

------

## 四、服务器准备（首次部署）

```bash
ssh Liyibin@8.141.121.22
sudo mkdir -p /opt/choutuan
# 把 docker-compose.prod.yml 放到 /opt/choutuan/
```

无 `.env`：本项目没有任何密钥或后端配置。

> ⚠️ 端口在 `docker-compose.prod.yml` 里是 `9000:80`，先确认服务器 9000 未被占用：
> `sudo lsof -i :9000` 应为空。

------

## 五、加载镜像并重建容器

```bash
sudo docker load -i /tmp/choutuan-web.tar.gz

cd /opt/choutuan
sudo docker compose -f docker-compose.prod.yml up -d --no-deps web

sleep 3
```

> **关键坑（同驭流）**：换镜像必须 `docker compose ... up -d` 重建容器，
> `docker restart` 只会继续跑旧镜像。compose 里**服务名是 `web`**，容器名是 `choutuan-web-1`。
> 验证镜像确实换了：
>
> ```bash
> sudo docker inspect choutuan-web-1 --format '{{.Image}}'
> sudo docker images choutuan-web:latest --format '{{.ID}}'
> ```

------

## 六、数据持久化（无）

**本项目服务端零状态**，无 volume、无数据库、无备份恢复环节：

| 数据                         | 位置               | 持久化方式                     |
| ---------------------------- | ------------------ | ------------------------------ |
| 购物车 / 订单 / 收藏 / 周报 | 访问者浏览器       | `localStorage`（用户侧自持）   |
| 站点文件                     | 镜像内（只读）     | 随镜像发版                     |

> 换镜像/重建容器不会影响任何用户数据——数据根本不在服务器上。

------

## 七、验证

```bash
curl -sf http://127.0.0.1:9000/health
# {"status":"ok","app":"choutuan"}

# 首页
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:9000/
# 静态资源（数据层 JS + 任一商品图）
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:9000/js/data.js
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:9000/img/shop_s01.webp
```

全部 200 即正常。

> 应用为 **hash 路由**（`#/home`、`#/report`），无需 history 回退配置；
> 未知路径已在容器 nginx 里 `try_files` 兜底回首页。

## 域名与 Nginx（首次部署）

1. **DNS**：在 `cloudwaveai.cn` 的解析里加两条 A 记录 → `8.141.121.22`：
   `www.choutuan` 与 `choutuan`。

2. **宿主机 Nginx**：把仓库里 `deploy/nginx-host-choutuan.conf` 放到服务器：

   ```bash
   sudo cp nginx-host-choutuan.conf /etc/nginx/conf.d/choutuan.conf
   sudo nginx -t && sudo systemctl reload nginx
   ```

   server 块反代到 `127.0.0.1:9000`，与驭流/作图工作台的规范一致。

3. **HTTPS 证书**：

   ```bash
   sudo certbot --nginx -d www.choutuan.cloudwaveai.cn
   ```

   > ⚠️ **只签有 DNS 记录的域名**。certbot 签发是全有或全无：只要命令里
   > 有一个域名解析不存在（如未加 A 记录的裸域 `choutuan.cloudwaveai.cn`），
   > 整张证书都会签发失败 → 443 上没有本站块 → https 请求落入其他项目的
   > 默认 443 块 → 浏览器报 HTTP 500"目前无法处理此请求"。
   > 若要裸域也可访问，先加 A 记录、`dig` 确认生效，再把 `-d choutuan.cloudwaveai.cn` 加回来。

4. **验收**：浏览器打开 <https://www.choutuan.cloudwaveai.cn> ——
   首页 40 家店铺流可滑动、进店加购、下单后骑手配送每 15 秒推进一阶段。

## 九、本地冒烟测试（部署前可选）

```bash
docker run -d --name choutuan-test --platform linux/amd64 \
  -p 9001:80 choutuan-web:latest
curl -sf http://127.0.0.1:9001/health && \
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:9001/
docker rm -f choutuan-test
```

> 用 9001 避开 9000，不影响后续部署。
